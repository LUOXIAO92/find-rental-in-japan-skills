# 日本の賃貸物件の検索と検証

この分野では、日本の賃貸物件の検索、絞り込み、物件ごとの検証、結果の統合を一括して扱う。スキルの入口はこのファイルのみとし、個別の機能や知識資料は通常の reference 文書として整理する。

主エージェントは、条件、優先順位、検証方法、進行管理、進捗の共有、上位判断のみを担当する。収集エージェントはサイト別または地域別に並列で動き、まず共通条件によるサイト内の絞り込みと一覧での追加選別を行う。独立した merge resolver が重複排除、事実の食い違いの調整、統合・並べ替え、統一文書の維持を担当する。各物件エージェントは1件または少数の物件を並列で担当し、すべての項目を検証したうえで、自ら独立した再確認エージェントを作成し、修正後に結果を提出する。

文書全体の一覧は [contents.md](contents.md) を参照する。以下のタスクに応じて関連する reference を開き、すべての文書や付録を既定で読み込まない。

## 必要に応じて読む付録

- 物件サイトの選択や追加、出典の網羅範囲の判断が必要な場合 → [物件サイト参考資料](references/appendix/housing-sites.md)。収集工程から必要に応じて参照する。
- ユーザーが光回線や住宅のネットワークに要件を設けており、接続方式や技術的な証拠を理解する必要がある場合 → まず [住宅ネットワークの検証](references/internet.md) を読み、次に問題に応じて [光回線参考資料](references/appendix/fiber-reference.md) を読む。
- 特別要件について、事業者の対応建物から募集中の物件を逆引きする方法が適している場合 → [事業者情報からの逆引き](references/appendix/provider-reverse-lookup.md)。これは補助的な入口であり、逆引きで得た候補にも共通条件の一次選別、重複排除、住戸ごとの検証が必要である。

## 共通原則

- 現在のユーザーの条件を基準とする。予算、面積、部屋の広さ、ネットワークプラン、礼金、通勤の希望、例外は、すべて今回のタスクで決める。
- 共通条件はまずサイトの絞り込み機能を使い、その後に一覧の項目を補足確認する。続いて merge resolver が重複排除・統合を行い、個別物件ごとに並列で完全な検証を行う。すべての広告を先に詳しく調べてはならない。
- 特別条件は、必要な事実に対応した独立の証拠で検証する。内装や配置などの定性的な条件は、詳細、間取り図、該当する部屋の写真を確認し、広告のタグや築年数で判断を代用しない。
- 各物件には明確な担当者を1人置く。証拠不足で他の物件の作業を止めない。独立した再確認エージェントの作成とフォローはその担当者が行い、主エージェントは物件ごとの細かな再確認を行わない。
- 事実、出典、照会時刻、適用範囲を残す。建物の設備、具体的な部屋番号、広告の条件をそれぞれ対応付け、食い違いを明記する。
- 現在の環境で利用可能な並列処理能力に応じてタスクを組み、モデルやランタイムの呼び出しに依存させない。独立したエージェントを使えない場合は、同じ役割を順番に実行し、「自己点検のみ、独立した再確認は未実施」と明記する。役割が独立していたと偽ってはならない。
- このスキルは検索、検証、整理を目的とする。仲介会社への連絡、個人情報の提出、予約、申し込み、契約は、ユーザーの別途の許可に従って扱う。
