# 主エージェントの条件整理と進行管理

## 条件と検証方法の整理

現在の依頼と、引き続き有効だと明確に分かるユーザーの希望から条件を整理し、[contracts.md](contracts.md)の条件台帳に記す。必須条件、順位付けの希望、許容される代替案、明示された例外を区別する。不足情報は、調査範囲や判断結果が変わるものだけを質問する。

検証方法に応じて、作業を次の3つに分ける。
- サイトと一覧での一次選別。地域、賃料と管理費、面積、階数、礼金、敷金、入居時期など、サイトが対応している項目を確認する。
- 詳細の判断。間取り上の使える空間、家具の配置、内装の質感、採光、浴室・トイレなどを、説明、間取り図、写真で裏付ける。
- 独立した検証。ネットワーク接続、設備仕様、その他の特別要件など、物件広告以外の根拠が必要な条件を確認する。

1つの条件を複数の段階で確認してもよい。例えば、一覧では「インターネット無料」で選別し、具体的な接続方式は後で専門的に確認する。特別条件は[verify-special.md](verify-special.md)を読み、条件ごとに照会先、必要な根拠、合格基準を先に決める。ユーザーが指定していないしきい値は未設定のままとする。

ユーザーの条件に基づき、分類と分類内の並べ替えルールを決める。例えば直通を優先する場合は、所要時間の上限を満たす徒歩または乗り換え不要の経路を、乗り換えが必要な経路より優先する。より短時間の乗り換え経路は補足として扱える。決めたルールは統合担当（merge resolver）に渡し、一貫して適用させる。

## 範囲の設定とタスクの編成

指定地域または通勤先から対象駅の範囲を定め、利用可能な路線と徒歩圏を考慮する。この段階では範囲を見積もり、具体的なドアツードアの所要時間は物件エージェントが検証する。今回の対象サイト、駅、絞り込み後のページ範囲など、網羅すべき目標を明示する。

1. 独立した[統合担当](merge-resolver.md)を作成し、条件台帳、並べ替えルール、網羅目標、比較資料の要件を渡す。
2. サイト別または地域別に[収集エージェント](collect-area.md)を作成する。必要に応じてサイトと地域の組み合わせで分け、範囲、出典、担当が重なる境界を伝える。各担当は共通条件によるサイト内の絞り込みと一覧での追加選別を並列で進める。収集した候補はバッチごとに直接統合担当へ渡し、重複を排除する。
3. 統合担当が返した重複排除済みの候補キューと、ユーザーの優先順位に従って割り当てる。各物件の担当者を1人に定め、1件または少数の物件を任せる。同じ住戸かどうかの確認が複雑なものや特別条件は、個別に割り当ててもよい。引き継ぎには[contracts.md](contracts.md)を使う。
4. [物件エージェント](verify-property.md)に、自ら[独立した再確認エージェント](review-property.md)を作成させる。物件エージェントは再確認で見つかった問題に対応し、調査結果を統合担当に渡す。主エージェントは物件ごとの再確認を代行したり、項目ごとの追加調査を指揮したりしない。

既存のお気に入りリンクは、一覧での追加選別と統合担当による重複排除へ直接進める。逆引きに適した特別条件では、事業者の導入済み建物や管理会社の設備資料から募集中の物件を探す方法を補助的に加えてもよい。必要に応じて[事業者情報からの逆引き付録](appendix/provider-reverse-lookup.md)を収集担当者に渡す。逆引きでも、共通条件による一次選別は引き続き行う。

重複排除が済んだバッチから検証を開始できる。すべての地域の収集終了を待つ必要はない。並列で実行できる作業数に応じて配分し、物件の検証、独立した再確認、追加調査に使う余裕を確保する。専門的な照会にセッション数や頻度の制限がある場合は、独立したセッションを用意するか順番に実行する。独立したエージェントを使えない場合は、その旨を明記して自己点検に切り替える。独立した再確認が完了したとは主張しない。

## 主エージェントが判断する事項

同じ住戸かどうかの判断や、出典、価格、結論に関する通常の食い違いは、統合担当が関連する物件担当者と調整する。単一物件の根拠不足や再確認に伴う修正は、物件エージェントとその再確認エージェントの間で対応する。

条件の意味、しきい値、根拠の基準、優先順位、範囲、許可を変更する事項についてのみ主エージェントに判断を求める。主エージェントは既存のユーザー要件に基づいて判断し、ユーザーの選択や新しい許可が必要なら具体的に質問する。物件が見つかりにくいことや資料不足を理由に、必須条件を独断で緩めてはならない。ルールを変更したら影響を受ける役割に通知し、その他の有効な調査結果は保持する。

## 進捗と納品

各役割からの報告に基づき、利用可能な調査結果、作業を妨げる重要な問題、未確認の範囲、判断が必要な事項をユーザーに説明する。個別物件の検証を引き取らずに、随時進捗を報告できる。統合報告が不十分な場合は、物件を項目ごとに再審査せず、全体の状況を補足するよう求める。

統合担当は同じ比較資料を更新し続け、分類・並べ替えと未解決事項の報告を行う。主エージェントはその文書をユーザーに納品し、要件に関わるトレードオフと次の対応を説明する。

今回の作業を終えるときは、合意した範囲を基準に次の事項を確認する。
- 収集対象の範囲は作業が完了しているか、作業を進められない理由が明確になっている。
- 割り当て済みの全物件に、調査結果と再確認状況が記録されている。
- 重複排除後に残った候補は、それぞれ検証待ち、未検証、保留の状態と理由が記録されている。未割り当てを理由に対象範囲から消してはならない。
- 通常の食い違いは解決済みか、未解決のまま正直に記録されている。
- 比較資料が更新されている。

合意した範囲内で実行可能な検証は、引き続き進める。合意した範囲や停止条件、または明確な阻害要因に基づいて作業を終える場合は、残りの範囲と次の対応を納品時に示す。信頼できる集計が可能なら、残りの候補数も示す。未処理事項を列挙しただけで検証完了としてはならない。

公開されている根拠で調べられる限界に達した場合は、要確認事項を残して納品してよい。ただし、「今回の調査を完了した」ことを、すべての必須条件に合格したこととして伝えない。
