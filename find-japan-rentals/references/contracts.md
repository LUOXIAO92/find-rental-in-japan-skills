# 簡潔な引き継ぎと結果の取り決め

簡潔なMarkdownを使い、大規模なJSON、重複するシステムメタデータ、操作ごとのログは求めない。テンプレートから該当しない項目を削除してもよいが、正確な識別情報、証拠の適用範囲、担当者、未解決事項は残す。

## 条件ファイル：主エージェント → 各役割

再確認エージェントは物件エージェントが作成し、同じ条件ファイルを受け取る。

- ユーザーの目的、出力言語、地域／駅の範囲、入居時期、通勤先と時間の算定基準
- 条件ごとに：内容、優先順位、必須／希望、共通／詳細／特殊、検証方法と合格に必要な証拠
- 費用の算定基準：月額予算に含むもの、敷金・礼金・その他初期費用についてのユーザーの基準値、未指定の上限は空欄にする
- ユーザーが明示的に認めた条件の緩和、代替案、例外とその適用条件。未承認の緩和は加えない
- 分類・並べ替えのルール、合意した調査範囲、まだ確認が必要な質問と除外・推薦への影響

## 収集結果の引き継ぎ：地域エージェント → merge resolver

### 範囲と網羅状況
- 地域／駅、情報源と検索リンク、閲覧日時（タイムゾーン付き）
- 実際に適用した絞り込み、一覧での追加絞り込み、補完検索、確認済みのページ番号／範囲
- 状態：この範囲の収集完了／一部完了／作業不能。残りの範囲と具体的な理由
- 集計基準：広告数、識別済みの独立した賃貸住戸数、識別未確定数。不明な場合は正確な数値を省略する

### 候補：建物名 · 部屋番号または仮識別子
- 識別情報：建物の別名、住所、部屋番号、階数、面積、間取り、重複の疑いがある対象と理由
- 広告：情報源と掲載者、広告への直接リンク、閲覧時刻。ページ記載の更新日／入居日は別々に記録する
- 共通の事実：賃料、管理費／共益費、月額合計と算定基準、敷金、礼金、その他判明している固定費
- 共通条件の判定：適合／不適合が判明／不明。根拠、適用するユーザーの例外
- 検証に回す事項：識別情報、価格の矛盾、欠落項目、詳細／特殊条件の手がかり

## 物件の割り当て：merge resolverがキューを提供し、主エージェントが担当者を配置

- 正確な対象：1戸または少数の賃貸住戸の識別子、すべての広告への直接リンク、同一対象と判断した理由、未解決の重複関係
- 単独の担当者、条件ファイル、今回解決すべき問題。一覧の事実は手がかりにすぎず、情報源を自ら確認する必要がある
- 再利用可能な同一建物の証拠とその適用範囲。部屋番号、価格、間取り、写真、募集状況などは引き続き住戸ごとに確認する
- 納品：物件全体の検証結果、独立した再確認の状態、未解決事項をmerge resolverへ渡す。要約やリンクだけを返さない

## 独立した再確認への入力：物件エージェント → 自ら作成した再確認エージェント

まず要件、事実、情報源を渡し、望む結論から始めない：
- 元のユーザー条件、例外、並べ替えの優先順位、既定の検証方法と証拠基準
- 正確な物件識別情報、統合の根拠、識別上の不確実性。調査済みの範囲と未調査の範囲
- 項目ごとの事実、情報源への直接リンク、閲覧時刻、適用範囲。必要な図面、写真の位置、検索条件、原文の抜粋
- 矛盾、欠落項目、試した経路、公開情報の既知の限界
- 暫定結論は比較用に別記し、事実と判断を明確に区別する。「合格の確認」は求めない

## 再確認結果の返却：再確認エージェント → 物件エージェント

- 各項目：問題／影響を受ける条件、情報源の証拠と位置、必要な対応、現在の状態
- 状態は要修正、解決済み、公開証拠不足で要確認、再確認に制限あり。実質的な問題がなくても確認範囲を説明する
- 全体：再確認完了／再確認完了だが要確認項目あり／要修正／再確認に制限あり
- 修正後、影響を受ける部分を再確認する。明示された不明点は今回の再確認を終えても残してよいが、条件を満たしたように装わない
- 独立したエージェントがいない場合は「自己点検のみ、独立した再確認は未実施」とだけ記録し、上記の独立した再確認完了の状態を使わない

## 物件結果：物件エージェント → merge resolver

### 建物名 · 正確な賃貸住戸の識別情報
- 調査状態：今回実行可能な検証は完了／一部完了／作業不能。調査済みの範囲、未調査の範囲と理由
- 再確認状態：独立した再確認の結果、修正の要約、残る問題。独立した再確認が未実施の場合は明示する
- 情報源：広告または提供事業者ごとの直接リンク、閲覧時刻。公開／更新／入居日は情報源での意味に従って記す
- 現在の費用：賃料、管理費／共益費、月額合計、その他固定月額費用。敷金、礼金、保証料など判明している初期費用と付帯条件
- 空間：面積、階数、間取りと証拠。室内／間取り写真が該当する部屋、モデルルームや別室の写真であれば明示する
- 通勤：ユーザーの目的地、出発／到着時刻の基準、徒歩と乗り換え、算定日と情報源。必要な場合のみ検証する
- 特殊条件：項目別の結論、証拠、適用する建物／部屋の範囲。根拠のない推測を確認済みと書かない
- 事実と適合性：実証済みの内容、条件ごとの適合／不適合／不明、希望条件の評価と根拠
- 矛盾と不足：矛盾する情報源、欠落項目、誰に何を確認してもらう必要があるか。ページの「入居可」はリアルタイムの空室保証ではない
- 推奨分類と理由、ユーザーの例外が適用されるか。調査や再確認の完了によって不明な必須条件を覆い隠さない

通常の情報源間・物件間の矛盾はmerge resolverへ渡し、担当者による追加調査と再確認を調整する。条件、基準値、検証方法、範囲、承認の変更に関わる事項は別途主エージェントに判断を委ねる。進捗の要約は主エージェントにも報告してよい。

## 最終納品：merge resolverが統一Markdownを維持

ユーザーが選んだ言語を使い、未指定なら会話の言語を引き継ぐ。まず短い結論と既定の並べ替え基準を示し、続いて条件、網羅状況、統一一覧表、必要な住戸ごとの説明を示す。複数のエージェントの報告をそのまま積み重ねない。

主エージェントが示したルールに従い、例えば「優先／要確認／代替候補／除外」に分類する。必須条件への不適合が明らかな場合は除外する。ユーザーが明示的に認めた条件緩和や例外に該当する場合に限り、代替候補にできる。証拠不足は通常、要確認に分類し、不適合とも充足済みとも書かない。

各住戸に識別情報、主要費用と日付、間取り／写真、必要な通勤と特殊条件の結論、適合する理由、重要な不足情報、再確認状態、少数の直接参照リンクを残す。重要な結論の近くに根拠を示す。同一建物で共有する事実はまとめて参照してよいが、住戸ごとの識別情報と結論を統合して消してはいけない。

末尾に検証時刻、情報源／ページの確認範囲、未完了の範囲、具体的な次の対応を記す。重複排除後に未割り当て、または検証未完了の候補を漏らさず、待機中／未調査／保留、理由、残りの範囲、信頼できる集計が可能なら件数も示す。これらの状態は検証完了に数えない。収集完了、賃貸住戸の検証完了、独立した再確認の状態、外部への確認待ちを区別する。主エージェントには同じ文書と概要報告を渡し、ユーザーへの進捗・意思決定に関する連絡は主エージェントが担当する。
