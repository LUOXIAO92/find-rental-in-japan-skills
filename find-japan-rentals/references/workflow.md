# ワークフロー DAG

## 主エージェント、merge resolverと物件担当者

```mermaid
flowchart TD
    U[ユーザー条件] --> M[主エージェント：条件、優先順位、検証方法と範囲]
    M --> A[収集エージェント：サイト別・地域別に並行実行、共通のサイト内絞り込み後に一覧で追加絞り込み]
    M --> D[独立したmerge resolver：地域をまたぐ重複排除と候補キュー]
    A --> D
    D --> S[主エージェント：キューに沿って単独の物件担当者を割り当て]
    S --> P[物件エージェント：各自が1件または少数の物件を完全に検証]
    P -->|自ら作成し要件、事実、情報源を渡す| V[当該物件の独立した再確認エージェント]
    V --> J{再確認での発見事項}
    J -->|修正可能な問題| R[物件担当者：対象を絞った追加調査と修正]
    R --> V2[同じ再確認エージェント：影響を受ける部分を再確認]
    J -->|証拠が十分、または公開情報の限界に到達| T[物件担当者：結論、不明点、再確認状態を保持]
    V2 --> T
    T --> H[merge resolver：識別情報、情報源、物件結果を統合]
    H --> K{報告間の事実は一致しているか}
    K -->|通常の事実の矛盾| C[merge resolver：関係する物件担当者を調整]
    C --> P2[関係担当者：追加調査し、自ら独立した再確認を手配]
    P2 --> H2[merge resolver：修正を統合、または未解決の事実を保持]
    K -->|一致| F[merge resolver：既定ルールで分類と並べ替え]
    H2 --> F
    F --> O[merge resolver：統一文書と状態の概要報告を維持]
    O --> L[主エージェント：結果と判断待ち事項をユーザーに報告]
```

サイト別／地域別の収集タスクは並行実行できる。共通の初期絞り込みが完了した一群から先に重複を排除し、該当物件の完全な検証を並行して開始する。すべての収集タスクを待つ必要はない。収集と準備済み物件の検証はパイプラインとして並行実行でき、収集結果はバッチごとに引き継ぐ。merge resolverは識別情報、情報源、結果、文書を独立して維持し、主エージェントはリソースと方向性を担当する。再確認エージェントは該当する物件エージェントが作成し、その物件エージェントに結果を返す。主エージェントが作成して物件ごとに審査する形にはしない。

条件の意味、基準値、検証方法、優先順位、範囲、承認に変更がある場合のみ、主エージェントに判断を求める。通常の事実の相違はmerge resolverが物件担当者を調整して対応する。主エージェントは各役割の概要報告を基にいつでもユーザーへ進捗を報告でき、図の最終納品まで待つ必要はない。

## 1件の物件内

```mermaid
flowchart TD
    I[物件タスクと検証要件] --> A[物件担当者：広告、建物、部屋番号を照合]
    A --> B{基本条件と有効性}
    B -->|続行可能| C[費用、入居、契約の確認]
    B -->|続行可能| D[説明、間取り、室内写真の判断]
    B -->|続行可能| E[必要に応じてドア・ツー・ドアの通勤を検証]
    B -->|続行可能| F[必要に応じて独立した専門検証を実行]
    C --> G[物件担当者：元の事実と項目ごとの証拠を統合]
    D --> G
    E --> G
    F --> G
    B -->|明確な不適合| H[ユーザーのルールに従い代替候補か除外を仮決定し、未調査範囲を記す]
    B -->|識別情報や状態が不明| K[追加調査、または不明点、矛盾、必要な情報を保持]
    H --> G
    K --> G
    G -->|担当者が自ら作成| R[独立した再確認エージェント：要件、識別情報、証拠、判定を確認]
    R --> J{再確認結果}
    J -->|追加調査可能な問題あり| P[物件担当者：追加調査と修正]
    P --> R2[同じ再確認エージェント：影響を受ける結論を再確認]
    R2 --> N[物件担当者：修正、不明点、再確認状態を保持]
    J -->|実質的な問題なし、または公開証拠の限界に到達| N
    N --> O[物件担当者：物件全体の結果をmerge resolverへ渡す]
```

費用、詳細、通勤、専門確認は依存関係がなければ並行実行できるが、物件担当者は常に物件全体の結果に責任を持つ。専門分岐は独立した再確認と同じではない。不明点を明示すれば今回の再確認を終えてよいが、それによって不明な必須条件を合格にすることはできない。追加調査可能な問題が未解決の場合や情報源にアクセスできない場合は、そのまま明記する。代替候補や除外済み物件の他の条件を引き続き確認するようユーザーが求めた場合は、承認された範囲内で実行する。

両図では追加調査と再確認を前向きのノードに展開し、循環しない構造を維持している。さらに追加調査が必要な場合は、新たな修正ノードを展開する。単独物件の問題は物件担当者が追跡し、物件間の事実の問題はmerge resolverが調整する。範囲やルールが変わる場合のみ、主エージェントによる再編成が必要になる。独立したエージェントを使えない場合は、同じ責任分担で自己点検し、「独立した再確認は未実施」と明示する。順番に行う自己点検を、図の独立した役割のように装わない。
