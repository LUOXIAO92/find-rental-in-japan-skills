# 逐房源完整核验

用于merge resolver去重后由主agent分配给房源核验者的候选。每个核验者负责一套或少量具体房间，独立完成各套房间的全部核验；不要把所有房源拆成互不衔接的费用组、通勤组和照片组。

## 输入与交付

- 输入：merge resolver给出的房源标识、归并依据与链接、用户硬条件和偏好、共同条件预筛结果、通勤目的地与时间要求、主agent确定的特殊条件核验方案
- 沿用 [contracts.md](contracts.md) 的共同结果格式；预筛结果只作为线索，详情页仍需核对影响入选的字段
- 每套房间单独交付：身份与有效性、条件逐项结论、费用与合同、户型与照片判断、通勤结果、适用的特殊核验、来源及查询时间
- 交付完整结论和待确认事项，不只交付链接、图片或某个分支结果。未核实的硬条件保留为待确认，不包装成通过

## 1. 锁定具体房间与当前募集状态

1. 核对楼名及别名、完整地址、栋号、楼层、房号、面积和户型；没有公开房号时保留可区分该房间的字段及身份不确定性
2. 对齐重复刊登的租金、管理费、户型图和照片。不能确认是同一房间时，不合并费用或证据；把跨来源或跨房源的未决冲突交merge resolver协调，仍由本房源负责人补查
3. 记录当前广告能否打开、刊登或更新时间、募集状态、可入住时间。页面仍存在不能单独证明房间仍空置或可申请
4. 区分“募集中”“空室”“入住日期可商议”等原文状态；已结束募集的广告不能继续作为有效推荐
5. 若用户有入住期限，以当前可入住日期及必要手续时间核验；信息不足则指出还需谁确认什么

## 2. 详情条件、费用与合同

- 逐项重核用户硬条件；网站没有筛选能力的条件在这里读详情，不因列表未显示而推断不满足
- 记录普通借家或定期借家、合同期、更新或再契约条件、更新费、短期解约条款；再契约可能性不等于保证续住
- 拆分月付：租金、管理费／共益费及明确强制的其他月费；可选服务另列，避免把总月支出写成裸租金
- 拆分初期费：敷金、礼金、仲介费、保证公司费、保险、换锁、清扫和其他明确强制项目；注明税额、返还条件及尚未报价项
- 初期总额只能按已知入住日期、日割规则及报价计算；有缺项时给已知小计或有依据的估算，写清假设，不给伪精确总价
- 检查退去清扫费、解约预告期和适用违约金；区分广告已披露条款与仍需合同／管理方确认的条款
- 相同字段有冲突时保留来源、日期与差异，不按较低费用或较宽松条件拼出一个不存在的方案

## 3. 户型、实景与居住感受

1. 查看实际户型图及可获得的室内照片，记录可回到原页的链接、图片序号或其他定位；没有看过图片就不做视觉评价
2. 区分本房间实拍、同楼其他房间、同户型参考、样板间及效果图；参考照片不能证明该房间装修状态
3. 把判断落到用户标准：例如房间形状和可用墙面、家具摆放、厨房与居室关系、采光遮挡、收纳、设备及可见老旧程度
4. 标注观察事实与主观评价，写出判断依据；“新”“漂亮”“宽敞”不替代具体证据，也不从照片推断不可见的隔音或气味。装修质感、是否显旧等定性条件结合实拍与详情判断；建造年份、翻新年份或“リフォーム済”等标签只能提供线索，不能单独证明当前室内状态
5. 图纸与照片不一致、照片角度不足或缺少关键空间时，明确影响哪项判断及需要补充的照片或现场确认

## 4. 按用户场景核验通勤

- 从楼栋入口附近到用户指定目的地入口，按要求的工作日、出发／到达时段查询可复现路线；地址不完整时标明定位精度
- 输出门到门总时长、起终点步行、乘车区段、换乘次数及路线查询链接／时间；说明路线是否已计入候车和站内换乘，避免重复相加
- 广告“车站步行几分”只作线索，不能用最近车站到目标车站的乘车时间代替通勤总时长
- 用户要求直达或偏好少换乘时，实际核对是否需要换车；线路贯通运行与同站换乘分开说明
- 在相同时间口径下比较候选；班次、出入口或定位不确定造成的误差保留为估计，不把导航结果写成保证用时

## 5. 特殊条件与收束

仅在用户有特殊条件时读取 [verify-special.md](verify-special.md)，执行主agent给定的核验方案。具备工具时，可并行委派彼此独立的限定检查，但本房源核验者仍负责核对房间身份、汇总证据和补齐整套交付。

按共同格式给出通过、不通过和待确认项；写明影响入选的理由及最小下一步。硬条件已有明确失败证据时可停止无助于决策的后续检查，注明哪些部分未继续，不伪装成全部核验完成。

## 6. 自行创建独立复核并交付

完成整套初查后，由本房源agent使用当前可用的并行能力创建独立复核agent，交给它[review-property.md](review-property.md)和[contracts.md](contracts.md)的复核输入。先给原始用户要求、已查事实和来源，再另列拟定结论；不能要求它认可预设结果，也不能把专项分支的检查直接算作整套独立复核。

收到复核的“问题／证据／所需动作／状态”后，自己补查或修正，再交同一复核agent检查受影响部分。普通事实冲突由merge resolver协调相关负责人；条件、阈值、验证方法、范围或授权需要改变时升级主agent，不私自放宽。

公开资料达到边界时，可与复核agent按明确未知收束：保留缺项、对适配的影响及最小确认问题。若缺口仍能合理补查则继续；来源受阻、范围受限或可补查问题未解决均如实记录，不能假称已通过复核。无独立agent能力时执行自查，标明“仅自查，未独立复核”。

将修正后的整套结果、复核状态和未决事项交[merge resolver](merge-resolver.md)，由其归并、排序和维护文档。向主agent提供进度或升级事项即可，不要求主agent逐套复核。新证据影响既有结论时，负责补查并再次复核受影响部分，再增量交付。
