# 主agent：条件与编排

## 整理条件与验证方法

从用户当前请求及明确延续的偏好提取条件，使用[contracts.md](contracts.md)的条件档案。区分硬条件、排序偏好、允许的备选和明确例外，只询问会改变范围或判断结果的缺失信息。

按验证方式安排工作：
- **网站与列表初筛**：地区、租金与管理费、面积、楼层、礼金、押金、入住时间等网站支持的字段。
- **详情判断**：户型可用空间、家具摆放、装修质感、采光、卫浴等，需要说明、户型图或照片支持的条件。
- **独立验证**：网络接入、设备规格或其他特殊要求，需要房源广告以外的证据。

条件可以跨阶段：列表先筛“网络免费”，具体接入方式再专项核实。每项特殊条件先确定查询入口、所需证据和通过标准，见[verify-special.md](verify-special.md)。用户未指定的阈值保持未设定。

确定类别及类内排序规则。例如用户要求直达优先时，符合时限的步行或无需换乘路线优先于必须换乘路线；更快的换乘时间可作补充。规则由用户条件决定，交给merge resolver一致执行。

## 划定范围与编排任务

从指定地区或通勤目的地确定站点范围，考虑可行线路和步行区。此时做范围估计，具体门到门时间由房源agent核验。为本轮声明网站、站点和筛选后分页等覆盖目标。

1. 创建独立的[merge resolver](merge-resolver.md)，交付条件档案、排序规则、覆盖目标及统一文档要求。
2. 按网站或区域创建[收集agent](collect-area.md)，必要时切分为网站与区域组合，提供范围、来源和重叠边界；并行执行共通条件的站内筛选、列表补筛后，批次直接交merge resolver去重。
3. 依据merge resolver给出的去重候选队列和用户优先级，为每套房源确定唯一负责人，分派一套或少量房源。复杂身份或特殊条件可单独分派，交接见[contracts.md](contracts.md)。
4. 要求[房源agent](verify-property.md)自行创建[独立复核agent](review-property.md)，处理复核问题后，把结果交merge resolver；主agent不代做逐套复核或逐项补查指挥。

已有收藏链接直接进入列表补筛与merge resolver去重。适合反查的特殊条件可补充从提供商导入楼栋或管理公司设备资料反查在租房源，按需将[提供商反查附录](appendix/provider-reverse-lookup.md)交给收集者，仍执行共通条件初筛。

已去重的一批即可启动核验，不必等所有区域收集结束。按可用并行能力分配资源，为房源核验、独立复核和补查保留空间；专项查询有会话或频率限制时安排独立会话或顺序执行。没有独立agent能力时采用明确标记的自查降级，不声称完成独立复核。

## 处理范围、规则与授权升级

普通的身份、来源、价格和结论冲突由merge resolver协调相关房源负责人；单套证据缺口和复核修正留在房源agent与其复核agent之间。

只有改变条件含义、阈值、证据标准、优先级、范围或授权的事项升级到主agent。依据已有用户要求作决定；需要用户选择或新授权时提出具体问题。不得因房源难找或资料缺失自行放宽硬条件。规则变化通知受影响角色，保留其他有效结果。

## 进度与交付

依据各角色报告向用户说明可用结果、重要阻塞、覆盖缺口和需要决定的事项；可以随时报告进度，无需接管逐套核验。合并报告不足时要求补齐汇总状态，而非重新逐项审查房源。

merge resolver维护同一份统一文档、执行分类排序并报告未解决事项。主agent据此交付用户、解释与需求相关的取舍及下一步。

本轮收束以约定范围为准：收集范围完成或明确受阻；每个已分派房源有结果及复核状态；去重后的其余候选逐一注明排队待核验、尚未核验或暂缓及原因，不能因未分派而从覆盖中消失；普通冲突已解决或如实保留；统一文档已更新。约定范围内仍可执行的核验继续推进；若依据用户约定的范围、停止条件或明确阻塞收束，应在交付中披露剩余候选数量（可可靠计数时）、范围及下一步，不把列出待办等同于完成核验。公开证据已达边界可以带待确认项交付，不将“完成本轮调查”说成全部硬条件已通过。
