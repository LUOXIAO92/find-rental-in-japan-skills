# 可选专项：住宅网络

本文件是 [verify-special.md](verify-special.md) 的可选示例，仅在用户提出网络要求时读取。用本次用户的用途、阈值和容忍范围制定通过条件；不默认指定运营商、付费方式或网络架构。

需要厘清光纤接入类型、服务名词或技术证据时，按需读[光纤参考](appendix/fiber-reference.md)。需要从覆盖或导入楼栋寻找在租房源时，再读[提供商反查](appendix/provider-reverse-lookup.md)；它只补充候选入口，不证明本房间已安装或通过条件。

## 先拆清用户要求

- 区分所需事实：光纤是否到户、是否已有可用线路、能否新装、带宽及上行要求、共享限制、费用、开通期限
- 用户排斥“整栋共享 1G”时，明确其关注的是楼栋上联容量、共用户数、到户介质还是拥塞体验；按其实际定义核验
- 如果只要求适合远程办公或上传，先确定必要指标及可接受的不确定性；不要自行等同为必须专线、必须有偿或某品牌

## 建立楼栋与房间身份

1. 固定邮编、都道府县至番地、楼名及别名、栋号与房号；将官方查询返回地址与房源逐项匹配
2. 官方系统不识别别名时可用已验证地址查找，不以附近建筑或同名楼的结果代替
3. 记录查询允许确认到小区、楼栋还是房间；无法定位具体房间时保留该限制

## 分开核验接入、状态与性能

- 接入介质：区分光纤到住户的 FTTH、楼内 LAN、VDSL、同轴；“光回线”“高速”“互联网对应”等广告词不足以确定到户介质
- 可提供与已装好：官方地址查询可提供服务，不等于本房间已有线路、端口、终端或可立即开通；区分覆盖、可申请、待施工、已安装及已激活
- 新装条件：确认管理方允许的施工方式、共用部及室内布线限制、可用端口和合理开通时间；不能仅凭运营商覆盖就保证能安装
- 速率：分别记录套餐下行与上行标称值、是否尽力而为、上传限速／公平使用／流量限制等适用条款；套餐峰值不等于实测速率
- 体验证据：测速需对应线路、套餐、时间及有线／无线方式；其他住户测速只作补充，不能保证本房间的持续吞吐量或延迟

## 针对共享容量作出判断

如果用户条件涉及楼栋总上联，按其通过标准核验共享层级、上联容量，以及判定确实需要的覆盖户数、增容或带宽分配说明。用户只设上联容量阈值时，共享户数可作补充信息，不额外设为通过门槛。

- 区分每户套餐速率、楼内交换机上联、楼栋外联和运营商接入网共享；不能用“每户最高 1G”证明楼栋不存在共同瓶颈
- 缺少影响用户通过标准的容量或共享数据时，该项记待确认；不依据总户数推算真实共享人数，也不用简单均分当作实际可用速率
- PON 接入存在共享并不自动违反用户条件；按用户针对的共享层级和容量判定，不把 FTTH 自动当成独享
- 免费／租金内含／一括契约和单独付费只是计费与契约安排；都不能单独证明通过或失败

## 查询与证据组合

1. 使用运营商当前官方页面、地址查询及套餐条款，记录查询条件、匹配对象、结果和日期；不依赖预设的私有接口或猜测的接口参数
2. 向管理方或业主的现有说明核对本栋布线、网络合同、总上联与施工许可；需要外联时由房源负责人向主agent提交具体对象、缺项问题及授权需求
3. 中介详情页或答复可提供线索，但涉及接入结构、实际装机及共享容量的结论应找到对应技术资料或负责该设施的管理方确认
4. 运营商说明与管理方信息回答不同问题：前者通常说明可提供的产品，后者说明本栋实际配置；一方不能自动替另一方证明所有事实
5. 多个来源冲突时由房源负责人保留差异，核对地址、更新时间和“可提供／已安装”的口径；跨来源或跨房源的未决冲突交merge resolver协调。涉及用户网络阈值、共享定义或证据标准变化才升级主agent；冲突未解决时不选有利说法通过

## 单房源回传

使用 [contracts.md](contracts.md) 的共同格式，补充：精确匹配对象、到户介质、现有／可申请状态、适用套餐及上下行、用户关心的共享容量与户数、费用与工期、来源、结论和待确认问题。

只有证据覆盖本次网络硬条件才判通过。只查到运营商品牌、可提供服务或广告“网络免费”时，明确已知部分和缺项，交回房源核验者并入完整房源结果。由该负责人创建的独立复核agent检查身份、技术证据和条件判定，负责人补查或修正后交merge resolver；公开资料不足可以明确未知收束，不能因此判通过。
