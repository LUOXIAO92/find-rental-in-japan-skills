# ワークフローDAG

## 主エージェント、統合担当、物件担当者の分担

```mermaid
flowchart TD
    U[ユーザー条件] --> M[主エージェント：条件、優先順位、検証方法、範囲を決める]
    M --> A[収集エージェント：サイト別・地域別に並列で収集し、検索条件と一覧で候補を絞る]
    M --> D[独立した統合担当：地域をまたぐ重複を除き、検証待ちの候補を管理]
    A --> D
    D --> S[主エージェント：検証待ちの候補ごとに担当者を1人割り当て]
    S --> P[物件エージェント：各自が1件または少数の物件を全項目について検証]
    P -->|自ら作成し、要件、事実、情報源を渡す| V[その物件の独立した再確認エージェント]
    V --> J{再確認の結果}
    J -->|修正できる問題あり| R[物件担当者：問題のある箇所を追加調査して修正]
    R --> V2[同じ再確認エージェント：修正の影響を受ける部分を再確認]
    J -->|根拠が十分、または公開情報で調べられる限界に達した| T[物件担当者：結論、不明点、再確認状態を記録]
    V2 --> T
    T --> H[統合担当：識別情報、情報源、物件ごとの結果をまとめる]
    H --> K{報告の事実関係は一致しているか}
    K -->|通常の事実の食い違いあり| C[統合担当：関係する物件担当者と調整]
    C --> P2[関係担当者：追加調査し、自ら独立した再確認を手配]
    P2 --> H2[統合担当：修正を反映し、未解決の事実は明記]
    K -->|一致| F[統合担当：決められたルールで分類して並べ替え]
    H2 --> F
    F --> O[統合担当：比較資料と進捗の要約を更新]
    O --> L[主エージェント：結果と判断待ちの事項をユーザーに報告]
```

サイト別・地域別の収集は並列で進められる。共通条件の一次選別が済んだ候補から、まとまった単位で統合担当（merge resolver）に渡す。重複を除いた物件は全項目の検証を並列で始められるため、すべての収集タスクの終了を待つ必要はない。収集を続けながら、準備ができた物件の検証も進める。

統合担当は識別情報、情報源、調査結果、比較資料を独立して管理する。主エージェントは作業の割り振りと進め方を担当する。再確認エージェントは物件エージェントが自ら作成し、その物件エージェントに結果を返す。主エージェントが作成して物件ごとに審査する形にはしない。

条件の意味、基準値、検証方法、優先順位、範囲、承認を変える場合だけ、主エージェントに判断を求める。通常の事実の食い違いは、統合担当が物件担当者と調整する。主エージェントは各役割の報告を基に、いつでもユーザーへ進捗を伝えられる。図の最後の提出まで待つ必要はない。

## 1件の物件を調べる手順

```mermaid
flowchart TD
    I[物件タスクと検証要件] --> A[物件担当者：広告、建物、部屋番号を照合]
    A --> B{基本条件と掲載情報の有効性}
    B -->|続行可能| C[費用、入居、契約の確認]
    B -->|続行可能| D[詳細説明、間取り、室内写真を確認して判断]
    B -->|続行可能| E[必要に応じてドアツードアの通勤を検証]
    B -->|続行可能| F[必要に応じて独立した専門検証を行う]
    C --> G[物件担当者：元の事実と項目ごとの根拠をまとめる]
    D --> G
    E --> G
    F --> G
    B -->|明確な不適合| H[ユーザーのルールに従って代替候補か除外かを仮決定し、未調査範囲を記す]
    B -->|識別情報や状態が不明| K[追加調査するか、不明点、矛盾、必要な情報を記録]
    H --> G
    K --> G
    G -->|担当者が自ら作成| R[独立した再確認エージェント：要件、識別情報、根拠、判定を確認]
    R --> J{再確認結果}
    J -->|追加調査できる問題あり| P[物件担当者：追加調査と修正]
    P --> R2[同じ再確認エージェント：修正の影響を受ける結論を再確認]
    R2 --> N[物件担当者：修正内容、不明点、再確認状態を記録]
    J -->|実質的な問題なし、または公開情報で調べられる限界に達した| N
    N --> O[物件担当者：物件全体の結果を統合担当へ渡す]
```

費用、詳細、通勤、専門的な確認は、互いの結果を待つ必要がなければ並列で進められる。ただし、物件全体の結果には常に物件担当者が責任を持つ。専門的な確認を分担しても、独立した再確認を行ったことにはならない。

不明点を明記したうえで今回の再確認を終えてよい。ただし、不明な必須条件を合格にしてはならない。追加調査できる問題が未解決の場合や、情報源にアクセスできない場合も、そのまま記す。代替候補や除外済みの物件について他の条件も調べるようユーザーが求めた場合は、承認された範囲で確認を続ける。

両図は、追加調査と再確認を後続のノードとして描き、循環しない構造にしている。さらに調査が必要なら、新しい修正ノードを後ろに追加する。1件の物件内の問題は物件担当者が追跡し、物件間の事実の食い違いは統合担当が調整する。範囲やルールを変える場合だけ、主エージェントが作業を組み直す。

独立したエージェントを使えない場合は、同じ責任分担に沿って自己点検し、「独立した再確認は未実施」と明記する。順番に自己点検しただけなのに、図のように独立した役割が確認したと装ってはならない。
